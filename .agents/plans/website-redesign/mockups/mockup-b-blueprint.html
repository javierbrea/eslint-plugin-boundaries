Why

Architecture decays one import at a time.

The diagram on the wiki says helpers never know about components. Then someone needs a quick fix, the import is three keystrokes away, and the review is busy. JS Boundaries makes the diagram executable.

  1. The lines are in your configElement and file descriptors map folders and files to the names you already use in design discussions.
  2. The rules read both sidesEach policy sees the element, file category and module origin of the importer and the imported, plus the import kind.
  3. Feedback is immediateThe editor underlines the import. CI fails the build. The message explains the architectural reason, not just the rule id.
  4. Adoption is progressiveStart with one layer and one policy on an existing project with the recommended config. Tighten with strict when ready.
How it works

From folder tree to enforced architecture in three edits

1

Classify files and elements

Element descriptors match folders. File descriptors match files on their own, so a file can be a component and a test at the same time. You only need one of the two to start.

settings: {
  "boundaries/elements": [
    { type: "helper",    pattern: "helpers/*" },
    { type: "component", pattern: "components/*/*" },
    { type: "module",    pattern: "modules/*" },
  ],
  "boundaries/files": [
    { pattern: "**/*.spec.js", category: "test" },
  ],
}
2

Write the policies

Pick a default, then allow or disallow by any combination of element type, file category, module origin and dependency kind. Captured path fragments let one policy cover a whole family of elements.

"boundaries/dependencies": [2, {
  default: "disallow",
  policies: [
    { from: { element: { type: "component" } },
      allow: { to: { element: { type: "helper" } } } },
    { from: { element: { type: "module" } },
      allow: { to: { element: { types: ["component", "helper"] } } } },
    { disallow: { to: { file: { categories: "test" } } },
      message: "Never import test files from ${from.element.type}s" },
  ],
}]
3

Read the error where you wrote the import

Violations are ordinary ESLint errors: editor squiggles, CI failures, templated messages with the element types on both sides. Six more rules cover entry points, external packages, private elements and unknown files.

src/helpers/format/index.js
  1:22  error  No rule allowing this dependency was found.
         File is of type 'helper'. Dependency is of type 'component'
         boundaries/dependencies

✖ 1 problem (1 error, 0 warnings)
Specification

What the plugin understands

classification
Three independent layersElement (the architectural unit), file (its own category) and module (where the import resolves). All three are computed for both sides of every dependency.
selectors
Match on anything describedTypes, categories, origins, captured path fragments and array queries. Reference the from side's captures in the to side.
policies
Allow and disallow, with a defaultPolicies are evaluated in order. Messages are templates with access to the full description of the dependency.
rules
Seven rules, one settingdependencies, entry-point, external, no-private, no-unknown-files, no-unknown-dependencies, no-ignored-dependencies.
performance
2.5× faster since 7.3Selectors are normalized once and message templates are cached, cutting lint time by 60% on real projects.
compatibility
ESLint 9, Oxlint, TypeScript, monoreposTyped config helpers (satisfies Config), custom resolvers and path aliases, per-package element roots.
New in v7

One file, described from every angle

Hover a layer to see the part of the runtime description it fills. Policies can read any of them, on both sides.

elementThe architectural unit: component, service, module…
fileThe file's own categories: test, index, style…
moduleWhere the dependency resolves: local, external, core.
// components/Price/Price.spec.tsx  →  import "react"
{
  from: {
    element: { types: ["component"], captured: { name: "Price" } },
    file: { categories: ["test"] },
    module: { origin: "local" },
  },
  to: {
    element: { types: [] },
    file: { categories: [] },
    module: { origin: "external", name: "react" },
  },
  dependency: { kind: "value", relationship: null },
}
