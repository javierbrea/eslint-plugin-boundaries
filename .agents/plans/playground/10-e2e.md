# Phase 10: the sanity suite of the website and the playground

Goal: a private Nx project, `test/website-e2e` (`website-e2e`), runs a sanity suite with Playwright in Chromium, at a desktop and a narrow viewport, against the built website. It reaches the page only through the page objects of phase 9 and those it adds, and CI runs it on every pull request.

Issue: #640, `closes #640`. Branch `test/640/website-e2e` from `feat/539/playground`; PR into `feat/539/playground`, title `test(website): check the website and the playground in Chromium`. Changelog: none (tests and CI). The PR description lists each spec with what it covers, and the acceptance criteria of #640 with how each one was checked.

Read first:

- Decision 22 of the index and issue #640.
- `test/browser-e2e` (`package.json`, `project.json`, `playwright.config.js`, `test/global-setup.js`, `eslint.config.js`, `AGENTS.md`, `README.md`): the model for the project, its targets and its docs.
- `.agents/rules/playwright-testing.md` and the `./playwright` entries of `playground` and `website`, from phase 9.
- `packages/website/scripts/screenshots.mjs`: the viewports (1440×900 and 390×844), the hosts whose errors are tolerated (`api.github.com`, `api.npmjs.org`) and the 404 path.
- `packages/website/src/pages/playground.tsx`, `src/components/OpenInPlayground/` and the `share` domain of the playground (`useShareLink` copies the link with `navigator.clipboard.writeText`).
- `.github/workflows/build.yml` (jobs `build`, `test-browsers` and `all-checks`), `publish.yml`, `publish-to-github.yml` and `.github/actions/install-browsers`.

Preconditions: phase 9 merged.

## Scope

In: the project, its fixtures and specs, the page objects the specs need (each beside its component, exported from its entry and mirrored from its jsdom sibling), CI, the spec sections of the rule and the docs of the project. Out: Firefox and WebKit, visual comparisons, the local app, and the detailed behavior of the playground, which stays in the jsdom specs.

## Steps

### Project

1. `test/website-e2e`, modelled on `test/browser-e2e`: `package.json` (private, `@boundaries/website-e2e`, with `website` and `@boundaries/playground` as `workspace:*`), `project.json`, `tsconfig.json`, `eslint.config.js`, `cspell.config.cjs`, `AGENTS.md`, `CLAUDE.md` (`@AGENTS.md`) and `README.md`. The specs are TypeScript, type-checked by `check:types`.
2. `test:e2e` installs Chromium (`playwright install chromium`) and runs `playwright test`. Its `project.json` makes it depend on the `build` of `website` and on the `build:playwright` of `playground` and `website`.
3. `playwright.config.ts`: Chromium only; a `desktop` project at 1440×900 and a `narrow` one at 390×844; a `webServer` that serves `packages/website/build` with `docusaurus serve` on a fixed port, without opening a browser; no retry locally, and one retry with a trace in CI. A spec that needs the panes runs only in `desktop`, skipped in `narrow` by a tag in its title and `grepInvert`, as the rule says.
4. Fixtures: `test` and `expect` extended with the root page objects, and a console listener that fails the test on an error, except for the requests to the hosts that `screenshots.mjs` tolerates.

### Specs

5. Website: from the home to the docs and the Quick start, through the navbar and the sidebar; `/this-page-does-not-exist/` shows the 404 page; none of those pages logs a console error or starts a web worker, which only `/playground/` does (#635).
6. Playground, `desktop`: `/playground/` without a hash loads the Quick start example (the tree lists its files, the problems panel its count, a file opens in the inspector); the example picker loads another example and changes the hash; Help opens and closes; Reset brings back the Quick start; a reload keeps the project on screen.
7. Open in playground, `desktop`: the button at the end of step 6 of the Quick start opens the playground with its project after a client-side navigation, and the same link visited directly opens the same project, not the one the store remembers.
8. Share, `desktop`: `page.addInitScript` replaces `navigator.clipboard.writeText` with a function that keeps the link; Share shows the copied message, and the kept link, opened in a new page, shows the same project and config.
9. Narrow: `/playground/` shows the desktop-only note and never requests the chunk of the playground, recognized by a string that only the chunk holds (open point).
10. Each page object a spec needs is added beside its component, exported from its entry and mirrored from its jsdom sibling. The specs hold no locator or selector.

### CI

11. `.github/workflows/build.yml`: the `test-browsers` job runs `pnpm nx check:all website-e2e` after `browser-e2e`, and the `check:all` of the `build` job excludes `website-e2e` as it excludes `browser-e2e`. `all-checks` already needs `test-browsers`. `publish.yml` and `publish-to-github.yml` run `pnpm check:all`, which now runs this suite too; check that they install Chromium through `install-browsers` before it.

### Docs

12. `.agents/rules/playwright-testing.md`: the sections on specs (only through page objects, the fixtures, the tags per project), determinism (no fixed wait; a test that passes only on retry is a defect to fix, never a reason for another retry, a longer timeout or a wait) and running the suite.
13. `test/website-e2e/AGENTS.md` and `README.md`: what the suite covers, how to run it and read a failure, and where a spec and a page object go. The `repo-architecture` skill lists the project and its dependencies.

## Verification

- `pnpm nx check:all website-e2e` passes locally, in both projects.
- Changing the test id of a component that a spec reaches fails the spec through its page object, and updating its two page objects fixes it without touching the spec (shown in the PR, not committed).
- The CI run of the PR shows the suite in `test-browsers`, and `all-checks` is green.
- `pnpm nx run-many -t check:all --all` passes.
- The acceptance criteria of #640 are checked in the PR description.

## From the worker (#635)

- The playground evaluates in a web worker, so the verdicts arrive after the shell renders: a spec waits for them with a web-first assertion on the status of the top bar or a verdict, never with a fixed wait. While an evaluation is late the status reads `evaluating…` (decision 23).

## Open points

- How the narrow spec recognizes the chunk of the playground. Default: by a string only the chunk holds, such as `ROOT_CLASS` (`jsb-play-root`, `packages/playground/src/ui-kit/helpers/theme/theme.constants.ts`), read from the bodies of the script responses; check first that no other script of the page holds it.
- The port of the `webServer`. Default: a fixed one other than 3000, so that a running `pnpm nx start website` never answers the suite.
