# T4: the config editor

Goal: `ConfigEditor`, the CodeMirror 6 editor of the config node: JSON5 highlighting themed by the tokens, the problems of the engine underlined at their range with the message on hover and marked in the gutter, a range that can be revealed, and the line highlight that phase 6 uses for "Open policy in config".

Read first: `README.md` of this folder (the `TextRange` and `ConfigProblem` types, in `src/engine/Engine.types.ts` once T2 is committed); `../00-shared.md` section 6 ("Panes", the config node; "Color", the code areas); the mockup's `config` and `policy` states (`../mockups/config-*.png`, `policy-*.png`, and the `.editor`, `.u-error`, `.u-warn`, `.lint-tip`, `.is-policy`, `.is-active-line` rules of `../mockups/playground.html`); research note 3 on #539 (`gh api repos/javierbrea/eslint-plugin-boundaries/issues/comments/6577804232 --jq .body`); the READMEs of `@codemirror/view`, `@codemirror/state`, `@codemirror/language`, `@codemirror/lint`, `@codemirror/commands` and `codemirror-json5` in `packages/playground/node_modules`.

## Files

- `src/ui/config/ConfigEditor.types.ts`: `ConfigEditorProps = { value: string; onChange: (value: string) => void; problems: readonly ConfigProblem[]; label: string; readOnly?: boolean; highlight?: TextRange; reveal?: { range: TextRange; key: number } }`. `reveal` scrolls the range into view and puts the cursor at its start each time `key` changes; `highlight` marks the lines of the range (13% `--jsb-code-keyword` with a 3 px bar) until it is unset.
- `src/ui/config/ConfigEditor.tsx`: creates the `EditorView` once in an effect and destroys it on unmount. A new `value` that differs from the document replaces it without moving the scroll; a user edit calls `onChange`. `readOnly` uses `EditorState.readOnly`. The content has `aria-label={label}`. Extensions: line numbers, the active line, history with its keymap and the default keymap (not `indentWithTab`, so that Tab leaves the editor), bracket matching, `json5()` of `codemirror-json5`, the highlight style, the lint gutter, and the problems pushed with `setDiagnostics` (no linter source: the engine is the source).
- `src/ui/config/EditorTheme.ts`: `EditorView.theme` and a `HighlightStyle` whose values are `var(--jsb-code-*)` and the mono font: background `--jsb-code`, text `--jsb-code-fg`, keys `--jsb-code-fg`, strings `--jsb-code-string`, numbers and booleans `--jsb-code-number`, comments and line numbers `--jsb-code-comment`, punctuation `--jsb-code-fg`; 12.5/22 px; the gutter of 18 px with ✕ and ▲ in `--jsb-code-error` and `--jsb-code-number` (CodeMirror's markers restyled with CSS masks of the paths of the mockup's `i-cross` and `i-warn` symbols; T3 writes the icon components at the same time, so this task does not import them); wavy underlines in the same colors; the tooltip as a card (`--jsb-card`, `--jsb-ink`, 1 px `--jsb-line-strong`, 3 px left border in `--jsb-bad` or `--jsb-warn`, body 12.5 px), with the title in bold and the detail below; selection and cursor readable on `--jsb-code`.
- `src/ui/config/Diagnostics.ts`: `ConfigProblem` → CodeMirror `Diagnostic` (`error` → `error`, `warning` and `deprecation` → `warning`), with `renderMessage` building the title and the detail; a URL in the detail becomes a `More info` link (read how `@boundaries/config` adds its docs links to a diagnostic).
- `src/ui/config/Highlight.ts`: the state field and effect of `highlight`.
- `src/ui/config/index.ts`.
- `src/ui/config/ConfigEditor.spec.tsx` and specs of the helpers: the text renders and highlights (a string token gets the string class), a typed change calls `onChange`, a new `value` replaces the document, problems become diagnostics at their ranges (`forEachDiagnostic`), `reveal` moves the selection, `highlight` adds and removes the line decorations, `readOnly` refuses edits, the view is destroyed on unmount. jsdom has no layout, so tests read the editor state, not coordinates.

## Notes

CodeMirror injects its own styles; they stay scoped by `EditorView.theme`. The editor lives inside the playground root, so its tooltips do too. T6 composes it in the config pane; this task does not add a pane head.
