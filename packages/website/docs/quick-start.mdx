# Quick Start

Follow these steps to quickly set up ESLint Plugin Boundaries in your project. Then you can explore more advanced configurations to fit your project's needs in the [Setup section](./setup/setup.md).


## 1. Installation

If you [have not installed them yet](./installation.mdx), install ESLint and ESLint Plugin Boundaries:

```bash
npm install eslint eslint-plugin-boundaries --save-dev
```

## 2. Register the Plugin

Once installed, enable the plugin in your `eslint.config.js` file:

<Tabs>
<TabItem value="JavaScript">

```javascript
import boundaries from "eslint-plugin-boundaries";

export default [
  {
    plugins: {
      boundaries,
    },
  }
];
```

</TabItem>
<TabItem value="TypeScript">

```typescript
import boundaries, { Config } from "eslint-plugin-boundaries";

export default [
  {
    plugins: {
      boundaries,
    },
  } satisfies Config
];
```

</TabItem>
</Tabs>

## 3. Define your Elements

The plugin needs to identify the elements in your project. To do so, define your elements using the [`boundaries/elements` setting](./setup/elements.md).

These patterns determine how each file or dependency is classified.

:::tip
Read the **[Elements](./setup/elements.md)** section for guidance on how to define the patterns for the elements in your project.
:::

<Tabs>
<TabItem value="JavaScript">

<CodeDiff language="javascript">{`
. import boundaries from "eslint-plugin-boundaries";

. export default [
.   {
.     plugins: {
.       boundaries,
.     },
+     settings: {
+       "boundaries/elements": [
+         { type: "helper", pattern: "helpers/*" },
+         { type: "component", pattern: "components/*/*" },
+         { type: "module", pattern: "modules/*" }
+       ],
+     },
.   }
. ];
`}</CodeDiff>

</TabItem>
<TabItem value="TypeScript">

<CodeDiff language="typescript">{`
. import boundaries, { Config, Settings } from "eslint-plugin-boundaries";

. export default [
.   {
.     plugins: {
.       boundaries,
.     },
+     settings: {
+       "boundaries/elements": [
+         { type: "helper", pattern: "helpers/*" },
+         { type: "component", pattern: "components/*/*" },
+         { type: "module", pattern: "modules/*" }
+       ],
+     } satisfies Settings,
.   } satisfies Config
. ];
`}</CodeDiff>

</TabItem>
</Tabs>

:::info
This is only a basic example of configuration. The plugin can also capture path fragments from element paths so you can reuse them in rule selectors. Read **[Elements](./setup/elements.md)** to learn the full range of descriptor options.
:::

## 4. Apply Predefined Rules

Apply one of the [predefined rule configurations](./setup/eslint-integration.md) as a starting point by extending it in your `rules` section.

:::tip
Use `recommended` for existing projects to introduce rules gradually — it allows files outside defined elements. Use `strict` for new projects to require all files to belong to a known element from the start.
:::

:::note
The `recommended` config includes some deprecated rule aliases, so you may see deprecation warnings in your console. They are harmless. See **[ESLint integration](./setup/eslint-integration.md)** to learn how to override them (for example, `"boundaries/element-types": 0`).
:::

<Tabs>
<TabItem value="JavaScript">

<CodeDiff language="javascript">{`
. import boundaries from "eslint-plugin-boundaries";

. export default [
.   {
.     plugins: {
.       boundaries,
.     },
.     settings: {
.       "boundaries/elements": [
.         { type: "helper", pattern: "helpers/*" },
.         { type: "component", pattern: "components/*/*" },
.         { type: "module", pattern: "modules/*" }
.       ],
.     },
+     rules: {
+       ...boundaries.configs.recommended.rules,
+     },
.   },
. ];
`}</CodeDiff>

</TabItem>
<TabItem value="TypeScript">

<CodeDiff language="typescript">{`
. import boundaries, { Config, Settings, Rules } from "eslint-plugin-boundaries";

. export default [
.   {
.     plugins: {
.       boundaries,
.     },
.     settings: {
.       "boundaries/elements": [
.         { type: "helper", pattern: "helpers/*" },
.         { type: "component", pattern: "components/*/*" },
.         { type: "module", pattern: "modules/*" }
.       ],
.     } satisfies Settings,
+     rules: {
+       ...boundaries.configs.recommended.rules,
+     } satisfies Rules,
.   } satisfies Config
. ];
`}</CodeDiff>

</TabItem>
</Tabs>

## 5. Set Dependency Rules

Now you can define your own dependency rules by using the [`boundaries/dependencies` rule](./rules/dependencies.md).

:::tip
Read how to use **[Selectors](./setup/selectors.md)** to configure your rules in more detail.
:::

:::tip
You can customize the error messages reported by rules using **[message templates](./setup/rules.mdx)**.
:::

<Tabs>
<TabItem value="JavaScript">

<CodeDiff language="javascript">{`
. import boundaries from "eslint-plugin-boundaries";

. export default [
.  {
.    plugins: {
.      boundaries,
.    },
.    settings: {
.      "boundaries/elements": [
.        { type: "helper", pattern: "helpers/*" },
.        { type: "component", pattern: "components/*/*" },
.        { type: "module", pattern: "modules/*" }
.      ],
.    },
.    rules: {
.      ...boundaries.configs.recommended.rules,
+      "boundaries/dependencies": [2, {
+        default: "disallow",
+        rules: [
+          {
+            from: { element: { type: "component" } },
+            allow: { to: { element: { type: "helper" } } }
+          },
+          {
+            from: { element: { type: "module" } },
+            allow: { to: { element: { type: ["component", "helper"] } } }
+          }
+        ]
+      }]
.    },
.  },
. ];
`}</CodeDiff>

</TabItem>
<TabItem value="TypeScript">

<CodeDiff language="typescript">{`
. import boundaries, { Config, Settings, Rules } from "eslint-plugin-boundaries";

. export default [
.  {
.    plugins: {
.      boundaries,
.    },
.    settings: {
.      "boundaries/elements": [
.        { type: "helper", pattern: "helpers/*" },
.        { type: "component", pattern: "components/*/*" },
.        { type: "module", pattern: "modules/*" }
.      ],
.    } satisfies Settings,
.    rules: {
.      ...boundaries.configs.recommended.rules,
+      "boundaries/dependencies": [2, {
+        default: "disallow",
+        rules: [
+          {
+            from: { element: { type: "component" } },
+            allow: { to: { element: { type: "helper" } } }
+          },
+          {
+            from: { element: { type: "module" } },
+            allow: { to: { element: { type: ["component", "helper"] } } }
+          }
+        ]
+      }]
.    } satisfies Rules,
.  } satisfies Config
. ];
`}</CodeDiff>

</TabItem>
</Tabs>

:::note
Flat selectors like `{ type: "component" }` still work and are converted automatically. The `{ element: { type: "component" } }` form shown here is the recommended way to also match a file's category or the resolved module — see **[Selectors](./setup/selectors.md)**.
:::
